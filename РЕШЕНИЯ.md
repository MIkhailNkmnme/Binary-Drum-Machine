# Решения по координации

Новые решения добавлять ниже. Изменяя прежнее решение, указывать, какое оно заменяет и почему.

## РШ-001 · 2026-10-23 · Самостоятельное распределение по сложности

Пользователь согласовал: координатор Astra/high; простые задачи Luna/low; обычная реализация Sol/medium; сложные задачи и проверка Astra/high. В инструментах этой среды Sol задан как gpt-6.1-sol, Luna — gpt-6-luna, Astra — gpt-6-astra. Координатор сам выбирает категорию. Ограничения наследования истории, доступности и переключения главного чата перечислены в КООРДИНАТОР.md. Фактические настройки проверять, а не выводить из роли.

## РШ-002 · 2026-10-23 · Состояние хранится в проекте

Инструкции, задачи, решения и передача состояния публикуются в Binary-Drum-Machine. Работа должна восстанавливаться без памяти GPT-аккаунта. Живые агенты и полная история чатов файлами не переносятся. Долгие отдельные чаты создаются по отдельному запросу пользователя; разовые независимые части можно делегировать субагентам по согласованной схеме.

## РШ-003 · 2026-10-23 · Публичный реестр и закрытые материалы

Binary-Drum-Machine публичный; zerkalius-rules закрытый. Реестр публикуем в первом, чтобы его можно было читать с любого аккаунта. Закрытые инструкции и старый общий журнал целиком не переносим. Изменять репозиторий может только аккаунт с разрешением GitHub.

## РШ-004 · 2026-10-23 · Подтверждаемый прогресс

Проценты считаются по проверенно выполненным критериям с известными весами. Неизвестное состояние — «не оценён». Общий процент всего проекта без определённого объёма не вычисляется. GitHub показывает последнее опубликованное состояние; фоновый мониторинг этим пакетом не создаётся.

## РШ-005 · 2026-10-23 · Единый свод кнопок

По новому поручению пользователя правила кнопок собраны в [КНОПКИ.md](КНОПКИ.md): общие требования, поздние замены, специальные исключения и известные расхождения реализации. Этот свод — точка входа для новых кнопок и последующей стандартизации существующих. Корневой и локальные AGENTS.md ссылаются на него. Старые варианты витрин не считаются автоматически выбранным стандартом. Задача документационная; миграция интерфейсов, Свитчер и замороженные копии самостоятельно не запускаются.


## РШ-006 · 2026-10-23 · Постоянный градиент кнопок

По выбору пользователя закреплено В07 в КНОПКИ.md v4: тёмный центр, плавно светлее к границам, без центральной линии. Эскиз сохранён в knopki/standart/gradient-reference.png. Обратный градиент и варианты с линией не выбраны. Градиент не меняется от состояния, состояние показывает обводка. Контраст и RGB отдельно не выбраны. Это уточнение норматива, массовая миграция приложений и отложенная КНП-003 не возобновляются автоматически.

## РШ-007 · 2026-10-23 · Возобновление интерактивной витрины

Пользователь назначил текущий чат координатором и прямо подтвердил продолжение КНП-003. Прежняя пауза из-за пересекавшейся работы снята: старый чат проверен и неактивен, рабочая копия чиста и совпадает с origin/main. Витрина knopki/standart/ закреплена за одним внутренним исполнителем Sol / medium; координатор ведёт общий реестр, принимает и публикует результат. Сверять актуальные 58 правил v7, сохранять семь схем v1.001 и поздние уточнения КН10, КН02, В14. Непроверенный черновик 57 правил из архива/stash не применять автоматически. Массовая миграция приложений не входит в задачу.

## РШ-008 · 2026-10-23 · Отдельный чат только по просьбе пользователя

Пользователь прямо уточнил: «отдельный чат создается по моей просьбе для задания». По умолчанию координатор назначает внутренних субагентов. Отдельный видимый чат для конкретного задания создаётся только по прямой просьбе пользователя создать такой чат; «делай», «продолжай» и назначение координатором этого не подразумевают. Способ исполнения называть явно. Для текущей КНП-003 сохраняется внутренний субагент, новый чат не создаётся. Уточняет РШ-002 и пункт 5 раздела постановки КООРДИНАТОР.md.
