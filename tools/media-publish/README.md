# Images API, хранение R2 и выпуск в VK

МЕД-001. R2 подключён 21.11.2026 для текущего Windows-пользователя: чтение бакета подтверждено. Исходники инструмента опубликованы в `be3a9f11`.
Проверки пользователем: тесты, синтаксические и браузерные прогоны не выполнялись.

Один профиль доступен всем сессиям Codex **текущей учётной записи Windows на этом
компьютере**, независимо от рабочего каталога. Другой пользователь или компьютер
не сможет расшифровать DPAPI. Инструмент не запускает фоновые задания.

## Установка зависимостей

Нужен Python 3.10+. Из PowerShell (путь к репозиторию при необходимости заменить):

```powershell
$tool = 'E:\GD\_pzl\Zerkulis\Binary-Drum-Machine\tools\media-publish\media.ps1'
$venv = Join-Path $env:LOCALAPPDATA 'Zerkalius\media-publish\venv'
py -3 -m venv $venv
& (Join-Path $venv 'Scripts\python.exe') -m pip install -r (Join-Path (Split-Path $tool) 'requirements.txt')
```

Скрипт намеренно не устанавливает библиотеки самостоятельно. Команды R2 используют boto3. Генерация Images API и подготовка черновиков работают на стандартной библиотеке Python. В GitHub Actions для фото VK отдельно устанавливается Pillow.

## Настройка и использование

```powershell
& $tool status
& $tool configure
& $tool list -Prefix 'image-journal-2026-11-20/'
& $tool upload -File 'C:\Pictures\own-image.png' -Key 'image-journal-2026-11-21/own-image.png'
& $tool prepare-vk -OutputDirectory 'E:\GD\_pzl\Zerkulis\_scratch\vk-drafts-20261121'
```

`configure` интерактивно запрашивает endpoint, Access Key ID и Secret Access Key;
оба ключа вводятся скрыто. Не передавайте ключи в аргументах, сообщениях, журналах
или файлах репозитория. Нужен ограниченный bucket `zerkalius-media` API token с
правами чтения и записи объектов. Удаления инструмент не выполняет.

Endpoint принимается только в виде
`https://<32-hex-account-id>.r2.cloudflarestorage.com` (также `.eu`, `.us`,
`.fedramp` перед `.r2`); без порта, пути и параметров. Bucket фиксирован:
`zerkalius-media`, публичная база — `https://media.1001100.online`.

Файлы находятся в `%APPDATA%\Zerkalius\connections\`:

- `r2.credentials.xml` — PSCredential, Secret Access Key зашифрован Windows DPAPI;
  Access Key ID хранится в поле имени пользователя и защищён ACL.
- `r2.config.json` — только endpoint, bucket и publicBase.

ACL каталога и файлов разрешают доступ только текущему SID и SYSTEM.
`configure` отказывается заменять существующий профиль. Для осознанной ротации
сначала отдельно сохраните и уберите оба файла из `connections`, затем настройте
профиль вновь. Не переносите credentials на другой компьютер: создайте новый
профиль там. Сам факт наличия файлов не подтверждает доступ к R2.

`status` не расшифровывает credentials и не обращается в сеть. `list` читает до
100 объектов; при усечении сообщает `truncated` и следующий token (автопагинации
нет). `upload` принимает один непустой PNG/JPEG/GIF/WebP до 50 МиБ, проверяет
сигнатуру, сохраняет SHA-256 в metadata и возвращает URL/хеш. Полная проверка
декодирования изображения не выполняется. Перезапись запрещена: HEAD и атомарный
PUT с `IfNoneMatch: '*'`; при отсутствии поддержки условного PUT — отказ.
При неопределённой сетевой ошибке сначала проверьте объект командой `list`:
неуспешный ответ клиента не доказывает, что сервер не получил PUT.

Ключи расшифровываются в памяти и передаются только в окружение дочернего Python.
Окружение родительской сессии не изменяется. Ключи не выводятся и не попадают
в аргументы процесса; другие процессы того же пользователя могут иметь доступ
к его памяти. Профиль не даёт доступа другим пользователям Windows.

## Генерация через OpenAI Images API

Ключ берётся из `OPENAI_API_KEY` или из защищённого профиля Windows. Команда
`configure-openai` принимает ключ скрытым вводом. Для расхода бонусных кредитов
выберите ключ проекта нужной API-организации и проверяйте расход в OpenAI Platform.

```powershell
& $tool configure-openai
& $tool generate-image -PromptFile 'C:\Pictures\prompt.txt' -File 'C:\Pictures\background.webp'
& $tool generate-image -PromptFile 'C:\Pictures\edit.txt' -Source 'C:\Pictures\pendulum.png' -File 'C:\Pictures\illustration.png'
```

Один вызов сохраняет одну картинку в свободный файл PNG, JPEG или WebP вне
репозитория. Без `-Source` используется Images API `generations`, с исходником —
`edits`. `-Model`, `-Size` и `-Quality` можно переопределить. Сверьте иллюстрацию
с исходным полем и только затем добавляйте её в выпуск. [Images API](https://developers.openai.com/api/docs/guides/image-generation)

## Черновики VK — только локально

`prepare-vk` читает текущий локальный `issledovanie/image-journal/index.html`:
`article.entry`, заголовок/описание, `figure`, `a[data-view-image]`, `figure-name`.
При необходимости укажите `-Journal` и `-JournalUrl`. Допускаются только прямые
HTTPS оригиналы с `media.1001100.online`. На каждую фигуру — одна картинка,
подпись и ссылка на anchor записи, стабильный ID из anchor+URL. Длинные
закодированные ссылки состояния из рецептов в подписи не копируются.

В **новом каталоге вне репозитория** создаются `drafts.json` и `drafts.txt`.
Существующие файлы не заменяются. JSON содержит исходные title/description,
название/описание картинки, URL журнала, anchor и целевую группу `240613453`.
Картинки не скачиваются. Это заготовки для последующей ручной проверки.

Подготовка черновиков работает локально. Для отправки действует отдельный способ ниже.

## Автоматический анонс выбранной записи в VK

Получите **пользовательский токен VK** через приложение, которому VK разрешает
методы стены и фотографий. Владелец токена должен иметь право писать от имени
сообщества «Zerkalis» (`240613453`). Экран «Работа с API → Ключи доступа» в самой
группе выдаёт ключ сообщества. Для `wall.post`, `photos.getWallUploadServer` и
`photos.saveWallPhoto` официальный контракт указывает тип `user`. Выдачу этих
прав для конкретного приложения проверяйте в кабинете разработчика VK.
[Методы стены](https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json) · [Методы фото](https://github.com/VKCOM/vk-api-schema/blob/master/photos/methods.json)

В GitHub сохраните пользовательский токен в репозитории сайта через **Settings
→ Secrets and variables → Actions → New repository secret** с именем `VK_USER_TOKEN`.
Для первичной проверки откройте workflow **Publish chosen image journal entries to VK**
и запустите его в режиме `check`. Этот режим проверяет чтение стены и получение
сервера загрузки фото. Отправку первого поста подтверждает ответ `wall.post`
с `post_id`. [Секреты GitHub Actions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)

Чтобы выбрать один анонс, добавьте в `issledovanie/image-journal/vk/` один
JSON-файл с якорем статьи и URL выбранного оригинала из этой статьи. Пример
формата заявки для золотого XOR.

```json
{
  "entry": "hub-xor",
  "image": "https://media.1001100.online/image-journal-2026-11-20/hub-xor-4k.png"
}
```

Пуш заявки в `main` запускает workflow. Он ждёт совпадения карточки на живом сайте,
загружает JPEG для ВК и публикует от имени группы текст со ссылкой на запись.
Если на стене группы уже есть её точная ссылка, выпуск пропускается. Пока заявка
остаётся в очереди, она может быть обработана следующим выпуском. Перед удалением
анонса из ВК уберите его заявку из очереди. Старые статьи и загрузки прямо из
Маятника попадают в ВК только при наличии отдельной заявки.

Каталог `.local-secrets/` исключён из
Git; не добавлять его принудительно и не включать в архивы. Пароль и способ
