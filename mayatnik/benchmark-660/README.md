# МАЯ-660: 70 запросов, четыре направления, первый кадр

Проверено 12 ноября 2026 на NVIDIA GeForce RTX 3090, драйвер 610.88,
Chrome 157.0.8103.40, Node 24.18.0. WebGPU: `nvidia / ampere`, без
программного адаптера. Измерения выполнены отдельно от других GPU-прогонов.

Это новый репрезентативный сценарий по прямому указанию пользователя
«просто рандом сделай»: 70 случайных строк длиной от 1 до 70.
Он не воспроизводит неизвестные пользовательские строки со снимка экрана.
Замер МАЯ-657 с одной строкой не описывал такую нагрузку; его исторические
результаты сохранены в соседней папке без изменений.

## Зафиксированные входные данные

- `queries.txt` и `queries.json`: xorshift32, начальный seed **660**,
  сдвиги 13/17/5, каждый бит — старший бит следующего состояния.
  Первые строки: `0`, `00`, `001`, `0100`, `11110`.
- Обычный Маятник влево (`pend`), одиночная вершина, пустой фон,
  **кадр 1**, построена ровно одна вершина.
- Размер выделен для N/3: при 16384 строках поле **38484×16384**,
  stride 1204 слова, anchor 19242, план 5718 вершин; при 8192 строках
  поле **19241×8192**, stride 603, anchor 9620, план 2859 вершин.
  План не означает, что все эти вершины уже построены.
- Все четыре прямых направления (`all`), объединённые чётности
  (`parity=-1`), шаг решётки 2, границы всего поля, `withoutBands=true`.
  Без инверсии, пропуска пустот, сквозных маршрутов и пропущенных индексов.
  По одному исходному варианту на каждую строку, `compact=true`.
- При наличии находок в обоих вариантах отдельно создаётся точный архив
  кадра тем же `archiveOnly` путём. Построение поля в поисковое время не входит.

Исходный вариант v1.011 целиком подаётся из Git
`d50855ff2dcd3926ad2fe907067c48350abd4a17`; изменения рабочего дерева
не могли изменить его во время измерения. Новый вариант — v1.013.
SHA-256 GPU-модуля до:
`01c61bca6ed5a197e74aadeb32ccf4968b2d149569dab1aa6f307271df48ad17`;
после:
`7773cbf1519568e91218d8071dba9142f68ecff4134a464a8bf5723af202b0c2`.

## Результаты

| Поле | Поиск до, с | Поиск после, с | Ускорение поиска | Всего с архивом до, с | Всего после, с |
|---|---:|---:|---:|---:|---:|
| 16384 | 40,7062 | 1,4640 | **27,80×** | 56,2570 | 15,0867 |
| 8192 | 13,5106 | 0,5064 | **26,68×** | 21,8039 | 4,1106 |

| Поле | Readback поиска до, байт | После, байт | Уменьшение | GPU dispatch до → после |
|---|---:|---:|---:|---:|
| 16384 | 184354800 | 312480 | 589,97× | 11380 → 560 |
| 8192 | 92173200 | 78400 | 1175,68× | 3918 → 142 |

Каждая величина — один запуск в новом браузере, не медиана. Время архива
зависит от передачи данных, OPFS и сжатия; разница полного времени не
должна целиком приписываться GPU-поиску.

Для 16384 новый поиск занял 1,464 с, затем архив — **13,622 с**:
полный readback 157810688 байт, передача/OPFS 7,9706 с, сжатие 4,8713 с.
Для 8192 архив после поиска занял 3,6038 с: readback 39518208 байт,
передача/OPFS 1,7416 с, сжатие 1,1383 с. Архив всё ещё читает обе полные
упакованные плоскости; сокращение readback в таблице относится к поиску.

## Что именно совпало

Для обеих высот `compare.cjs` строго сравнил настройки, геометрию и все
прежние семантические поля результата с помощью `assert.deepEqual`.
Найдены одинаковые **8 строк**, совпали выбранные координаты, направление,
чётность, порядок, текст и метаданные вариантов. Результаты находятся
в `comparison.json` и `comparison-8192.json`.

Полный вспомогательный `occurrenceCount` намеренно не сравнивается:
до изменения движок дополнительно считал 1039535294 совпадения на 16384
и 256947092 на 8192. Пользователь потребовал прекращать поиск уже
найденных строк. Новый обычный путь сохраняет точный выбор находок,
останавливает дальнейшую обработку слова, когда более ранний ответ уже
невозможен, и не выдаёт исчерпывающий счёт всех его вхождений.
Для диагностики полный счёт доступен с `countOccurrences:true`.
Отсутствующий полный счёт не означает незавершённый поиск строк.

Размеры архивов до/после одинаковы: 535141 байт для 16384 и 188308 для
8192. Это не утверждение побайтового равенства архивов.

Реальная GPU-проверка дополнительно прошла **102 сценария CPU/GPU**:

- прежние 52 случая: направления, половины, инверсия, пустоты и нули,
  границы слов и строк 127/128, обрезка, варианты, повторные слова,
  wildcard, пропуски, independentWords, bandBounds через настоящий worker;
- 44 случая с набором из 70 случайных строк, включая уже найденные
  индексы в `skip` и `skipByHalf`;
- 6 плотных случаев со всеми нулями или всеми единицами: 70 общих
  префиксов длиной 1…70 плюс три дубликата, разные требуемые количества,
  объединённые/раздельные половины и independentWords; обычный режим
  без полного счёта;
- аналитический полный счёт 69660 подтверждён при `countOccurrences:true`;
  отмена до запуска и сброс поля после реального progress с `done>0`
  заканчиваются `AbortError`. Неподдерживаемые сложные режимы возвращают
  `null` для обычного точного движка.

Это проверенные сценарии, а не доказательство для всех возможных входов.
Основной интерфейс проверен отдельным браузерным прогоном v1.013:
1/1 PASS, первичные данные — `app-flow.json`. На 8192 строках после
нахождения строки 0 следующий кадр передаёт `skip:[0]` и активную строку
1; после нахождения обеих строк очередной кадр не запускает GPU-поиск.
Сброс набора уже найденных строк выполняется при явном включении
«Каждый кадр». Этот сценарий интерфейса отделён от приведённых выше
сравнительных измерений 70 строк, которые напрямую вызывают движки.

## Повторение

Нужен установленный вне репозитория `playwright-core`.
Переменная `PLAYWRIGHT_PATH` задаёт абсолютный путь к пакету; по умолчанию
используется `$env:LOCALAPPDATA/Temp/mayatnik-benchmark-657/node_modules/playwright-core`.
`CHROME_PATH` может переопределить путь к Chrome.

Из корня проекта, PowerShell:

```powershell
node mayatnik/mayatnik-gpu-search-workload-benchmark.cjs baseline
node mayatnik/mayatnik-gpu-search-workload-benchmark.cjs current
node mayatnik/mayatnik-gpu-search-workload-benchmark.cjs parity
node mayatnik/benchmark-660/compare.cjs

$env:BENCH_HEIGHT='8192'
$env:BENCH_TAG='8192'
node mayatnik/mayatnik-gpu-search-workload-benchmark.cjs baseline
node mayatnik/mayatnik-gpu-search-workload-benchmark.cjs current
node mayatnik/benchmark-660/compare.cjs -8192
Remove-Item Env:BENCH_HEIGHT
Remove-Item Env:BENCH_TAG
```

Harness читает сохранённые `queries.json`, не создаёт новые строки при
каждом запуске. Он использует headless Chrome с
`--enable-unsafe-webgpu --disable-background-timer-throttling`.
Выходные JSON перезаписываются; перед новым сравнением сохранить
исторические свидетельства отдельно. Временные затраты на построение,
передачу, поиск и архив, полные опции и результаты записаны раздельно.
