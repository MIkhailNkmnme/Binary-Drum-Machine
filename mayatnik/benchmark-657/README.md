# МАЯ-657: точный поиск на RTX 3090

Измерено 12 ноября 2026 на NVIDIA GeForce RTX 3090, драйвер 610.88,
Chrome 157.0.8103.40, Node 24.18.0. WebGPU сообщил `nvidia / ampere`.
Программный адаптер не использовался. Браузер работал headless, с
`--enable-unsafe-webgpu --disable-background-timer-throttling`.

Исходный вариант: v1.005, Git `b5ab4369cb38780576e7172b1dbf1204719e3e6e`.
Его GPU, CPU-движок, OPFS worker и host подаются прямо из `git show`.
В исходный worker добавлены только измерители времени вокруг CPU matcher
и архива; условия поиска не менялись. Новый вариант: выпуск v1.007,
`mayatnik-gpu-search.js`, SHA-256 исполнявшегося файла
`5021271f086eaaa7964236bf269a7d7632be68ea5e8ce3cb2127320e5b0f9380`.

Каждая строка ниже — один запуск в новом браузере с заново построенным
полем. Это не медиана и не обещание такой скорости для любого запроса.
Построение поля записано отдельно в JSON и не включено во время поиска.
Производительные прогоны не пересекались с другими GPU-проверками.

## Одинаковые условия до и после

- Маятник влево (`pend`), одна вершина, пустой фон, диапазон N/3.
- 16384 строки: поле 38484×16384, stride 1204 слова, anchor 19242,
  кадр 5718. 8192 строки: поле 19241×8192, stride 603, anchor 9620,
  кадр 2859. Номер кадра здесь равен числу построенных вершин.
- Направление «Ряд» (`row`), обе чётности совместно (`parity=-1`),
  шаг решётки 2, всё поле, `withoutBands=true`, `compact=true`.
- Без инверсии, без пропуска пустот и сквозных маршрутов.
- Длинный запрос: `10011001100110011001100110011001`, находок нет.
  Короткий запрос: `101`, ровно одна выбранная находка.
- Архив включён в обоих вариантах: создаётся только при наличии находки.

## Полное время и передача данных

| Поле / запрос | До, мс | После, мс | Ускорение | Readback до, байт | Readback поиска после, байт |
|---|---:|---:|---:|---:|---:|
| 16384 / длинный, нет находки | 34732,4 | 102,4 | 339,2× | 157810688 | 393216 |
| 16384 / `101`, с архивом | 17171,1 | 13092,5 | 1,31× | 157810688 | 393216 |
| 8192 / длинный, нет находки | 8910,4 | 70,9 | 125,7× | 39518208 | 196608 |

В строке с находкой новый **поиск до начала сохранения занял 104,4 мс**.
После него архив отдельно потребовал 12987,7 мс, включая полный readback
157810688 байт, передачу/OPFS 7335,5 мс и сжатие 4930,3 мс.
Таким образом, уменьшение readback в 401,3 раза относится именно к поиску.
Сохранение точного кадра по-прежнему читает обе полные упакованные плоскости.
Ускорение поиска нельзя выдавать за такое же ускорение поиска с архивом.

Исходный поиск `101`: передача/OPFS 7389,4 мс, CPU matcher 743,7 мс,
сжатие 4632,9 мс. Исходный длинный запрос: CPU matcher 23088,1 мс.
Исходный `searchMs` **не включает** вычисление `bandBounds`; полное время
в таблице включает его, запуск worker, передачу, поиск и завершение.
Метрики worker могут не складываться ровно в total из-за подготовки
снимка, завершения OPFS и доставки результата.

## Точность и пределы проверки

`compare.cjs` выполнил `assert.deepEqual` всех семантических полей
результата до/после для трёх строк таблицы; настройки и геометрия также
совпадают. Дополнительные метрики `gpu` и `occurrenceCount` исключены из
этого сравнения. Находка `101` одинакова: строка 9, столбец 19239,
индекс 365595, шаг 2, длина 3. Архивы имеют одинаковый размер 28913468
байт; побайтовое равенство архивов этим не утверждается.

Дополнительно реальный GPU прошёл 52 сценария сравнения с CPU:

- Все четыре прямых направления и «Все», чётности -1/0/1/2,
  инверсия и обычное чтение, решётки с шагом 1 и 2.
- Отсутствующие клетки отличаются от присутствующих нулей; проверены
  переходы через границы 32-битных слов и строк 127/128.
- Обрезанные границы, явные cells, варианты, повторные запросы,
  пропуски выбранных строк/половин, independentWords, пробел в запросе,
  длинные слова. Автоматические границы нулей сверены с настоящим worker.
- Плотное поле с 69660 совпадениями: полный `occurrenceCount` совпал с
  аналитическим счётом, четыре выбранные находки — с CPU. Результат не
  обрезается из-за заполнения выходного буфера.
- Отмена до запуска и изменение поля из progress callback дают
  `AbortError`. Through, skipSpaces, серии, V и loop возвращают `null`
  для передачи обычному точному движку.

Синтетический растр 131×270 и сценарии не доказывают эквивалентность для
всех возможных входов.

Главное приложение проверено отдельным браузерным сценарием
`mayatnik-gpu-search-flow-browser.test.cjs` на поле 16398×8192 без CPU-растра.
`app-flow.json` фиксирует накопленные строки 0/1 и их жёлтый цвет в DOM,
режим «Каждый кадр», отсутствие дубликатов журнала при перерисовке,
восстановление сохранённого кадра 7 с битами `[1,0,1]` после замены поля,
выделение находки, ожидание результата настоящим `tick()` плеера,
отбрасывание результатов после выключения и смены кадра. Ошибок страницы нет.

Ядро зеркальной геометрии: 3/3. Старые тесты снимков, журнала, повторов и
выделения: 28/32. Четыре сбоя воспроизведены также на исходном `b5ab4369`:
две VM-фикстуры не задают `GROUP_COLOURS`/`parityValues`, ещё две требуют
отсутствующий jsdom по пути другого компьютера. Эти старые тесты не исправлялись;
их общий зелёный статус не заявляется. Три inline-скрипта HTML и изменённые
JS прошли синтаксическую проверку.

## Повторение

Установить `playwright-core` во внешнюю временную папку, не меняя зависимости
проекта; указать `PLAYWRIGHT_PATH` как абсолютный путь к этому пакету.
По умолчанию harness ищет его в
`$env:LOCALAPPDATA/Temp/mayatnik-benchmark-657/node_modules/playwright-core`.
При другом Chrome задать `CHROME_PATH`. Пример PowerShell из корня проекта:

```powershell
node mayatnik/mayatnik-gpu-search-benchmark.cjs baseline
node mayatnik/mayatnik-gpu-search-benchmark.cjs current
node mayatnik/mayatnik-gpu-search-benchmark.cjs parity

$env:BENCH_QUERY='101'
$env:BENCH_TAG='hit'
node mayatnik/mayatnik-gpu-search-benchmark.cjs baseline
node mayatnik/mayatnik-gpu-search-benchmark.cjs current
Remove-Item Env:BENCH_QUERY

$env:BENCH_HEIGHT='8192'
$env:BENCH_TAG='8192'
node mayatnik/mayatnik-gpu-search-benchmark.cjs baseline
node mayatnik/mayatnik-gpu-search-benchmark.cjs current
Remove-Item Env:BENCH_HEIGHT
Remove-Item Env:BENCH_TAG

node mayatnik/benchmark-657/compare.cjs
```

`BENCH_DIRECTIONS` принимает список через запятую, например `row,diag`.
Это изменит сценарии и результаты; в приведённой таблице измерен `row`.
Каждый запуск перезаписывает соответствующий JSON. Для сравнения другой
версии сначала сохранить эти свидетельства отдельно.

Первичные результаты: `baseline.json`, `current.json`, `baseline-hit.json`,
`current-hit.json`, `baseline-8192.json`, `current-8192.json`, `parity.json`.
Автоматическая сверка: `comparison.json`.
