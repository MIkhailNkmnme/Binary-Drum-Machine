**1. Аниматрица Code: символьная волна по столбцам**

Каждый столбец пересчитывается сверху вниз. Верхняя клетка остаётся прежней. Следующая клетка получает уже обновлённый символ сверху и свой прежний символ. Два одинаковых непустых символа взаимно уничтожаются, оставляя пустоту. Если встречаются два разных непустых символа, побеждает верхний. Пустота при сочетании с символом оставляет этот символ. Поэтому текстовый знак `0` и пустая клетка — разные состояния.

Когда в столбце остаются только пустота и один вид символа, их можно обозначить как 0 и 1:

```text
b[0] = a[0]
b[i] = a[i] XOR b[i-1]
```

Это в точности преобразование накопленной суммы по модулю 2, указанное среди способов построения узора Серпинского в [NKS, стр. 931](https://www.wolframscience.com/nks/notes-5-4--sierpinski-pattern/). Совпадение относится к двоичному оператору. Оно не означает, что весь переходный процесс с несколькими разными символами совпадает с обычным двоичным автоматом.

**2. Аниматрица Маятника/Excel: диагональная волна XOR**

Это другое семейство преобразований. Рассмотрим конкретный режим «2 ед / Строки / Вниз». Пусть A — двоичное поле до полного прохода, B — после него:

```text
B[0,x] = A[0,x]
B[y,x] = A[y,x] XOR B[y-1,x-1] XOR B[y-1,x+1]
```

Две верхние диагональные клетки уже пересчитаны, а целевая клетка ещё хранит прежнее значение. Ширина и высота фиксированы; значения за пределами поля равны нулю. Здесь взаимодействуют соседние столбцы. Записанный ноль также хранится отдельно от отсутствующей клетки.

Если D обозначает операцию XOR двух верхних диагональных соседей, то полный двоичный проход можно записать так:

```text
T = (I XOR D)^(-1)
  = I XOR D XOR D^2 XOR ... XOR D^(H-1), поскольку D^H = 0.
```

Вклад двух родителей соответствует правилу 90, а порядок пересчёта связан с [последовательными клеточными автоматами, рассмотренными в NKS, стр. 1034–1035](https://www.wolframscience.com/nks/notes-9-10--sequential-cellular-automata/). Однако совпадения локальной таблицы XOR недостаточно для тождества всей системы. В рассмотренных источниках точный опубликованный аналог полного прохода с такими же границами пока не установлен.

**3. XOR-Маятник: движущиеся конусы на сохраняемом поле**

Маятник сохраняет двумерное поле между проходами. За один проход конус пересчитывается сверху вниз: прежний бит целевой клетки складывается по XOR с двумя верхними диагональными соседями. Значения вне активного конуса остаются прежними. Вершина конуса движется по последовательности:

```text
0, -1, +1, -2, +2, ...
```

Конус с вершиной в a содержит клетки `(r, a-r+2j)`, где `j=0,...,r`, в пределах поля. Пустая вершина становится единицей. При расчёте первой строки под вершиной её значение временно читается как 1, затем сохранённое значение восстанавливается. Таким образом, маска конуса, движение вершины и порядок работы с вершиной входят в определение модели.

В приложении есть и расширенные маршруты вершин. Следующие две авторские GIF показывают вариант «пропуск нуля / обе стороны вместе» на исходном поле высотой 256 строк с заданным диапазоном вершин 1024. Они иллюстрируют этот расширенный режим; выше описан базовый маршрут с одним конусом за проход.

**Точка Встречи, оси и раскраска**

Ещё один предмет исследования — **Точка Встречи**, в которой сходятся диагональные направляющие. Она служит геометрическим ориентиром для изучения поля и выбора областей раскраски. Инструменты от точки выбирают начальные клетки вдоль столбца встречи либо по двум диагоналям, если встреча приходится между клетками. Затем режим «ТочкаОсь» распространяет цвет вниз и к оси по областям выбранного бита. Так можно прослеживать связные фигуры внутри большого симметричного рисунка.

**Уменьшение масштаба: другие симметричные картины в том же кадре**

При уменьшении масштаба в одном и том же записанном поле проявляются другие симметричные картины и мотивы. Я использую это как инструмент исследования: рисунок, рассматриваемый по отдельным клеткам, при уменьшении может приобрести другую видимую организацию. Исходный битовый кадр сохраняется, а экранный результат зависит от масштаба и способа выборки пикселей. Чтобы сравнение можно было повторить, нужно указывать кадр, коэффициент масштаба и способ отображения. В проекте есть [исследование одного кадра в разных масштабах с примерами изображений](https://1001100.online/issledovanie/Zerkalius-issledovanie.html#scale-one-frame).

**«Под полем»: сравнение разных разрешений рядом**

Инструмент **«Под полем»** размещает под оригиналом его версии с уменьшенным разрешением. Каждая версия получается из исходного кадра. Их можно показывать в одинаковом экранном размере, чтобы легче сравнивать изменения деталей и симметричных мотивов. Способ уменьшения и размер показа настраиваются отдельно. Выбранная нижняя копия также может служить маской раскраски или накладываться на оригинал через XOR, AND либо RGB.

В [примере, присланном автором][author-under-field], сохранён Маятник высотой 256 строк на кадре 32. Включён режим «Под полем», шаг высоты — восемь строк, способ уменьшения — как на холсте, размер показа — по оригиналу. Нижние разрешения идут как 248, 240, …, 8 строк. Также включена раскраска правилом Вольфрама 110: белый для результата 0 и чёрный для 1. Параметры прочитаны из сохранённой ссылки; нового запуска приложения для этого поста не было. **Наша раскраска «RGB-соседи»**

Цвет RGB кодирует локальное окружение из трёх битов одной строки. Для левого, текущего и правого битов `(L,C,R)` каналы задаются так:

```text
(красный, зелёный, синий) = (255*C, 255*L, 255*R)
```

Текущая клетка управляет красным каналом, левый сосед — зелёным, правый — синим. Получаются восемь цветовых классов:

| Слева — клетка — справа | Цвет |
|---|---|
| 000 | Чёрный |
| 001 | Синий |
| 010 | Красный |
| 011 | Пурпурный |
| 100 | Зелёный |
| 101 | Голубой |
| 110 | Жёлтый |
| 111 | Белый |

Например, в тройке `101` центральный бит равен нулю, но цвет получается голубым, поскольку оба соседа равны единице. Отсутствующие соседи дают ноль в канал; пустая клетка остаётся отдельным состоянием и не приравнивается к чёрному классу записанной клетки. В отражениях Аниматрицы соседи берутся на той же решётке: в исходном растре они расположены через два столбца.

Можно выбирать несколько цветовых классов и показывать их в цвете либо в виде чёрно-белой маски. Это позволяет выделять определённые сочетания битов и извлекать связные шаблоны. Поскольку заливка и инструменты шаблонов работают по отображённому результату, объединение классов может соединять области, которые в цветном виде были разделены. Исходное двоичное поле сохраняется. [Описание RGB и управления](https://1001100.online/mayatnik/instruction/#rgb).

**Раскраска таблицами правил Вольфрама**

Другой инструмент раскраски читает три бита строкой выше: слева, по центру и справа. Их трёхбитный код выбирает один результат из таблицы правила Вольфрама с номером от 0 до 255. Этот результат определяет один из двух цветов целевой клетки. В авторском примере выбрано правило 110.

Все входные значения берутся из существующего битового поля до ручной раскраски. Полученные цвета не подаются обратно на вход следующей строки. Верхняя строка сохраняет прежний цвет, отсутствующие соседи считаются нулями. Таким образом, знакомая таблица правила используется как цветовое отображение уже построенной геометрии Маятника. [Реализация и граничные условия](https://1001100.online/mayatnik/instruction/#wolfram).
