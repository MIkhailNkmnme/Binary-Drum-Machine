# Правила проекта

## Локальная инструкция восстановления · 2026-11-21

- `.local-secrets/` — только локальная папка владельца, исключённая из Git. Не добавлять через `git add -f`, не публиковать, не включать в общие архивы/экспорты, отчёты, скриншоты или вывод команд. Это прямое исключение пользователя из правила обязательной публикации материалов.
- Инструкция преобразования токена Cloudflare находится в локальной папке `.local-secrets/`. Точный путь указан в [памятке R2](tools/media-publish/README.md). Читать только для запрошенного подключения/восстановления, не печатать пароль и исходные ключи. Чтение инструментом может отразиться в истории чата; само по себе оно не является публичной публикацией.
- Публичная изменённая строка в tools/media-publish/README.md дана владельцем; способ преобразования неизвестен. Не угадывать и не называть её надёжно зашифрованной без проверки метода. После разрешённого восстановления хранить рабочие credentials только в локальном защищённом профиле.

## Общий доступ к медиа R2 · МЕД-001 · 2026-11-21

- Для работы с существующим бакетом `zerkalius-media` читать [tools/media-publish/README.md](tools/media-publish/README.md). Точка входа для локальных сессий — `tools/media-publish/media.ps1`. Начинать с команды `status`; наличие файлов профиля не доказывает действительность ключа.
- Настройки и защищённый ключ хранятся вне репозитория в `%APPDATA%\Zerkalius\connections`. Профиль общий для чатов текущего пользователя Windows; DPAPI не переносится на другой компьютер или другого пользователя. Там требуется отдельная настройка. Не просить пользователя присылать ключи в чат, не печатать их и не добавлять в Git.
- Публичные изображения доступны через `https://media.1001100.online`; R2 S3 API предназначен для загрузки. Для выпуска медиа достаточно Object Read & Write только на этот бакет; управление DNS, аккаунтом и другими бакетами не входит в задачу.
- Для загрузки через **Image Journal · R2 and VK** используем GitHub Actions Secrets `ZERKALIUS_R2_ENDPOINT`, `ZERKALIUS_R2_ACCESS_ID` и `ZERKALIUS_R2_SECRET`. Заявка с источником в GitHub Releases сначала загружает оригинал в R2 и сверяет SHA-256 на публичном домене. Анонс в ВК требует опубликованную запись и отдельный токен.
- `generate-image` делает один запрос к OpenAI Images API с локальным ключом пользователя. Для анонса в VK используется очередь явных заявок `issledovanie/image-journal/vk/` и секрет Actions `VK_USER_TOKEN`. `prepare-vk` готовит локальные черновики. При автоматическом выпуске сверять живую запись, права пользовательского токена и целевое сообщество «Zerkalis». Документация и проверка подключения описаны в [памятке медиа](tools/media-publish/README.md).

## Звук, музыка и голоса — только с нуля · 2026-11-18

Обязательно читать [ЗВУК.md](ЗВУК.md) перед работой со звуком, мелодией, голосом, музыкальным
генератором, звуковой дорожкой видео или экспортом. Во всех частях Зеркалиуса — только
собственная музыка и собственный процедурный звук с прослеживаемым исходником.
Записанные/аналоговые источники, человеческие записи, сэмплы, чужие мелодии и MIDI,
готовые голоса/модели с неподтверждённым происхождением запрещены. Обработка чужой записи
не делает её собственной. Разрешён сохранённый результат нашего математического синтеза.
NINETOZERO — пока только картинки, без звука. Описывать происхождение и способ сборки
каждого музыкального, голосового и видеовыпуска; правило действует во всех сессиях.

## Планы в общем гите · 2026-11-17

Перед началом работы в сессии каждый агент обязан записать своё намерение в `ПЛАНЫ.md` — что делает, какие файлы правит, чего не трогает — и закоммитить это в `main`. Работа без записи в планах считается невидимой второму агенту: её могут случайно повторить или перезаписать.

- Писать до первой правки, а не после.
- Обновлять статус, когда закончил или передумал; записи не удалять.
- Файлы перечислять явно: по этому списку разводятся конфликты.
- Общие файлы (`mayatnik/mayatnik-synthesis.js` и родственные) править только после согласования участка в `ПЕРЕПИСКА.md`.

## Обязательная публикация исследований и черновиков · 2026-11-13

Все исследования, черновики, оформленные разборы, рисунки, видео, данные и относящиеся к ним исходники по Зеркалиусу сохранять в Git и отправлять в соответствующий GitHub-репозиторий. Одних файлов в ответе, outputs или локальной папке недостаточно. Дополнительного разрешения на обычную публикацию этих материалов не требуется.

- Перед итоговым ответом с оформленным результатом выполнить commit/push и подтвердить удалённый коммит. В ответе дать ссылку на опубликованный материал; для веб-страницы проверить доставку GitHub Pages либо прямо отметить, что она ещё ожидается.
- Незавершённость исследования и отсутствие окончательной проверки не являются причиной оставить его только локально: публиковать с явным статусом «черновик», описанием неопределённостей и фактически выполненных проверок. Незавершённое исследование не объявлять доказанным или завершённым.
- Исследовательские страницы включать в навигацию Исследований. Сохранять полезные черновые сравнения и исходники рядом с результатом; временные зависимости, кэши и чужие несвязанные рабочие изменения автоматически не добавлять.
- Если отправка заблокирована, прямо написать «не опубликовано», сохранить подготовленный результат и следующий шаг. Не выдавать локальный файл или локальный коммит за доставку на GitHub.
- Сохранять разделение публичного сайта и закрытых правил: частный журнал и секреты не переносить в публичный репозиторий. Существующий порядок проверок и сохранения чужих изменений действует отдельно; новая норма не разрешает force push.
- Это постоянное правило по умолчанию. Агент не отменяет и не ослабляет его по собственной инициативе; будущие прямые указания пользователя рассматриваются по действующей иерархии инструкций.

## Координатор и продолжение работы (2026-10-23)

- Сначала прочитать [ПРОДОЛЖИТЬ.md](ПРОДОЛЖИТЬ.md), [КООРДИНАТОР.md](КООРДИНАТОР.md), [ЗАДАЧИ.md](ЗАДАЧИ.md), [РЕШЕНИЯ.md](РЕШЕНИЯ.md) и последние записи [ЖУРНАЛ.md](ЖУРНАЛ.md). Инструкции в подпапках также действуют.
- Пользователь разрешил координацию и делегирование: координатор сам определяет сложность и выбирает исполнителей по таблице в КООРДИНАТОР.md. Соблюдать доступные инструменты и ограничения среды; файл не переключает модели автоматически.
- Единый публичный источник задач — ЗАДАЧИ.md этого репозитория. После этапа обновлять карточку, журнал и краткое продолжение; публиковать проверенные изменения на GitHub. Ошибку публикации сообщать явно.
- До /compact, завершения сессии или передачи работы сохранить состояние в этих файлах. Не рассчитывать на память аккаунта, историю чатов или живых субагентов.
- Для работы из полного Zerkulis дополнительно читать родительские AGENTS.md, CLAUDE.md и журнал. Полный старый журнал и внутренние материалы из закрытого репозитория сюда не копировать.
- За общий реестр отвечает координатор; исполнители возвращают короткий отчёт и не редактируют его одновременно. Подробности распределения файлов, прогресса и публикации — в КООРДИНАТОР.md.
- Отдельный видимый чат для задания создавать только по прямой просьбе пользователя создать этот чат. По умолчанию использовать внутренних субагентов; «делай», «продолжай» и назначение координатором не разрешают создание отдельного чата. В отчёте различать субагента и видимый чат.

## Единый стандарт кнопок

- Перед созданием или изменением кнопок, групп, меню, ползунков и пультов читать [КНОПКИ.md](КНОПКИ.md). Это единый свод внешнего вида, размеров, расположения, подписей, состояний, сохранения и специальных исключений.
- Поздние уточнения пользователя имеют приоритет над прежними вариантами в пределах соответствующего вопроса. Таблица согласования и известные расхождения реализации находятся в КНОПКИ.md; существующий CSS и старые витрины не заменяют актуальное правило.
- Новые кнопки сразу делать по своду; существующие приводить к нему в рамках явно поставленной задачи. Эта документация не разрешает самостоятельно переделывать Свитчер и замороженные страницы.
- Алгоритм сокращения всех русских видимых подписей, исключения и полные подсказки — Т01–Т11 в КНОПКИ.md; локально не заводить другую трактовку.
- В живом Хабе (`index.html`, `_js/hub-*`) сохранять скрытые исходные контролы для логики меню; сокращать отображаемые подписи, не менять ключи сохранённой раскладки.
- `Zerkalius-hub-konus.html` — замороженная копия старого Хаба; живой Хаб — `index.html`.
