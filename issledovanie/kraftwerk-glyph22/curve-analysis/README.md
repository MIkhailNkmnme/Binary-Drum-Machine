# Глифы как идеальные кривые

ИСС-103 · 2026-11-13 · v0.004 · исследовательский черновик.

[Открыть просмотр](index.html) · [19 листов SVG](all-frames.svg) · [PNG](all-frames.png) · [ZIP](curve-analysis.zip) · [Независимая проверка](validation-report.md).

Модель включает все выделенные жёлтые линии, в том числе внутренние перекладины. Каждое клеточное ребро используется ровно один раз. Изгиб не создаёт соединений. Связный непустой граф допускает один штрих тогда и только тогда, когда имеет ноль или две нечётные вершины. Для нескольких компонент минимальное число штрихов равно сумме `max(1, odd/2)` по непустым компонентам.

Основная модель: 76 глифов, 18 допускают один штрих; 19 несвязны, ещё 39 связны, но имеют больше двух нечётных вершин. Это условные выводы о восстановленных графах. Исходная видеосъёмка местами не позволяет однозначно определить связи. Ответ об одном штрихе устойчив в 73/76 случаях при трёх порогах выделения; все выбранные показатели с учётом количества общих точек — в 41/76.

J — количество различных общих точек с тремя и более ветвями. На рисунках они обозначены X1… для четырёх ветвей и B1… для остальных; J = X + B. Для одного эйлерова прохода это различные точки повторного посещения, включая касание конца линии к её ранее пройденной части. Начальная/конечная запись разреза замкнутого штриха не добавляет пересечения. В JSON анализатора сохранены исходные метки J1…; отрисовщик разделяет их на X/B по степени узла, сохраняя идентификаторы точек.

## Воспроизведение

Нужны Node.js и Python с Pillow. Для повторного выделения — NumPy и opencv-python-headless.

```sh
node --test graph-analysis.test.cjs
node build-analysis.cjs
python render-lines.py
python build-page.py
```

`graphs.json` — входные графы с оценками линий, двумя пороговыми альтернативами и регистрацией решётки. `analysis.json` — обходы, длины в клеточных рёбрах и повторные посещения. `frames/` — 19 отдельных листов PNG/SVG; `overlays/` — 19 сопоставлений с исходной съёмкой. `extract.py` использует соседнюю папку `../drafts/witnesses/` и `../drafts/analysis/plate.py`. Отдельная диагностическая модель границ клеток не используется для основного вывода и не добавляет рёбра ради единого прохода.

В архив входят графы и все материалы этой папки, необходимые для повторного расчёта обходов и просмотра. Повторное выделение из съёмки требует соседних опорных кадров из первого исследования. Зависимости, кэши и полный интерфейс браузера в архив не включаются.

Проверено: 11 тестов, в том числе 400 случайных мультиграфов; независимая проверка 228 графов на однократное покрытие рёбер, непрерывность, минимальность и корректность посещений. Просмотрщик проверен в Chrome: выбор кадра, переключение масштаба и загрузка листов. Точность этих проверок не устраняет неопределённость оцифровки исходной анимации.

Уточнение первого исследования: опорные кадры 18 и 19 имеют одинаковые четыре восстановленных графа после переноса. Прежняя подпись о втором смешанном переходе исправлена; оба опорных изображения сохранены.

## Белая нить и XOR

[Интерактивный опыт](thread-xor.html) использует один замкнутый маршрут глифа 06/3: 48 уникальных рёбер и две точки самопересечения. Один, два и три полных прохода оставляют соответственно 48, 0 и 48 белых рёбер. В каждой точке пересечения 2, 4 и 6 посещений, поэтому она чёрная; обычный поворот считается одним посещением за круг. У замкнутой нити начало и конец отождествлены. Чёрные точки на экране увеличены для видимости.

`thread-xor.js` считает чётность рёбер и посещений узлов раздельно. `thread-xor-check.json` содержит проверку всех 145 целочисленных положений от 0 до 144 и соответствия маршрута исходным рёбрам. Две одинаковые нити на одном маршруте гасят весь след. Это демонстрация на восстановленном глифе, ещё не новая механика основного Маятника.

При разрешённых повторах двойная перемычка может исчезнуть в XOR и оставить видимые несвязные петли. Однако множество рёбер нечётной кратности одного непрерывного маршрута имеет ноль или две нечётные вершины. Поэтому XOR не устраняет все топологические ограничения. Отдельное гашение идеальной точки пересечения не меняет чётности числа рёбер.

Браузерная проверка опыта: 1/2/3 круга дали 48/0/48 белых рёбер и 2/4/6 посещений каждой точки пересечения. Проверены сброс, шаг ползунком, запуск и автоматическая остановка. Снимок — `thread-xor-viewer-checked.jpg`.

## AND, OR или XOR

[Разбор присланного глифа](boolean-thread.html) и [схема](boolean-thread.svg). Ручная осевая схема совпала с графами04/1 и13/1 после переноса; при всех трёх прежних порогах они имеют шесть нечётных узлов. В основной схеме49 единичных рёбер. Без повторения минимум3 штриха. Найдены и проверены минимальные маршруты: открытый51 шаг (2 повторных ребра), замкнутый52 (3). OR оставляет49 белых рёбер, XOR того же открытого маршрута47. Цветовая кодировка: белое=1; при белом=0 визуальное объединение записывается через AND. Точный генератор видео не установлен.

`node boolean-thread.cjs` воспроизводит граф, оба маршрута, сопоставление, проверки, таблицу истинности и SVG. Фотография пользователя сохранена без изменений в `boolean-thread-source.png`; `boolean-thread.json` содержит точные последовательности. Chrome: статья и схема просмотрены, снимок `boolean-thread-checked.jpg`.

Дополнение AND (статья0.002): построен отдельный путь A со всеми49 исходными рёбрами и двумя дополнительными дугами внутри верхних петель. Каждая дуга состоит из3 прямых отрезков. Проверен один открытый маршрут по всем55 различным отрезкам без повторов и без совпадения вдоль отрезка. Готовая маска B содержит только исходный глиф, поэтому A AND B возвращает его49 рёбер. Это требует второго слоя, который уже задаёт результат; полного совпадения физической нити с видимым следом здесь нет. `boolean-thread-and.svg`, `boolean-thread-and-checked.jpg`, данные `andMask` в JSON.

## Пунктирная нить из квадратов

[Новая гипотеза](dashed-thread.html) по предложению пользователя «1пусто1пусто». Подтверждено: каждый переход к следующей клетке, включая диагональный, — один шаг. Чередование не сбрасывается на поворотах. Проверенная петля пяти клеток имеет направления H,D,V,D,D, без прямых H↔V, в том числе при замыкании. Три диагональных шага дают нечётную длину; следующий круг приходит противоположной фазой. XOR после1/2/3/4 кругов:3/5/2/0 белых клеток; OR:3/5/5/5.

`dashed-thread.py` воспроизводит SVG/JSON стандартным Python. Статья и схема проверены в Chrome, `dashed-thread-checked.jpg`. Предыдущая пользовательская проба двух линий сохранена без изменений в `dashed-thread-two-lines-draft.png`. Форма звена (заливка/рамка/общая обводка) уточняется; решения для целевого глифа пока нет.
