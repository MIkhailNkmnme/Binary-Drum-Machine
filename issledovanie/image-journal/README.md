## Что публикуем

Каждый сюжет начинается с поля, кадра, обоев или исследования «Зеркалиуса». На карточке указываем название, дату, короткое описание и ссылку на источник. Для расчётного кадра даём кнопку «Открыть кадр» с готовыми настройками. Если результат был дорисован, добавляем «Как построить» и объясняем, что взято из источника и что изменено в обработке. Художественные работы подписываем «иллюстрация по мотивам» или «обработка через Image API».

| Сюжет | Что сохраняем для воспроизведения |
| --- | --- |
| Маятник | Режим «Треуг», число строк и вершин, направление, номер кадра, раскраску. В ссылке включены «Шрна по Оси» и «Верх», «Размер» выключен. Вершина у верхнего края, основание у нижнего, без отступа снизу. В серии на 1024 строки берём кадры, кратные четырём. Первая серия использует 4, 64, 176 и 508, а также «Медь», «Бирюзу», «RGB-соседи» и «Вольфрам 90». |
| Осевая раскраска | Один и тот же исходный кадр для сравнения, выбранные оси, цвета и правило раскраски. Области рассчитывает Маятник. Например, на кадре 64 показаны вертикаль, горизонталь и диагональ, а лист сравнения содержит восемь видов осей. |
| Хаб | Поле, операция, направление наложения, шаг и палитра. Для золотого XOR это поле 3 (5.8), шаг 4511, XOR, «Прямо» и «Рост». Полный кадр и обои 4K подписываем отдельно, у обоев отмечаем обрезку по бокам. |
| Иллюстрация | Ссылка на исходный мотив и объяснение, как он перенесён. Например, зеркало даёт вертикальный стык, Аниматрица Code — движение слева направо, ромбические обои — укладку граней. Если весь результат нельзя собрать в приложении, ссылка открывает источник мотива. |

Готовые примеры собраны в журнале. [Осевая раскраска](https://1001100.online/issledovanie/image-journal/#axes), [четыре кадра «Треуг»](https://1001100.online/issledovanie/image-journal/#treug), [сцена «Золотой XOR»](https://1001100.online/?scene=golden-xor), [иллюстрации](https://1001100.online/issledovanie/image-journal/#interpretations).

## Как готовим картинки через OpenAI API

1. Сначала строим исходное поле в «Зеркалиусе». Сохраняем ссылку с настройками и исходный PNG. Точные биты для исследования сохраняем отдельно от художественной версии. Для фактурного фона накладываем рассчитанный узор на отдельный фон, сохраняя его границы и клетки.
2. Для фона или иллюстрации по текстовому описанию вызываем `images.generate`. Если на входе есть конкретный экспорт Маятника или Хаба, вызываем `images.edit` и передаём файл. Для подбора цветов можно запросить у текстовой модели палитру в HEX, затем заново раскрасить исходный кадр в Маятнике.
3. В задании пишем, какую геометрию сохранить и какую часть разрешено менять. Например, «оставь один треугольник с вершиной у верхнего края, основанием у нижнего и теми же крупными пустотами; измени материал клеток на бирюзовую керамику». Для фона просим только фактуру без фигур, подписей, логотипов и элементов интерфейса.
4. Сохраняем исходник, итоговый файл, модель, промпт, размер, качество и краткое описание обработки. Для первых иллюстраций использовали `gpt-image-2`, `medium` и WebP. Для новых запросов выбираем модель и размер, разрешённые проектом API. Иллюстрации сверяем с исходником по общему силуэту, а в расчётных кадрах проверяем клетки и обрезку.

Ключ `OPENAI_API_KEY` читает локальный процесс из окружения. Для бонусных API-кредитов используем проект связанной API-организации и смотрим расход в API Platform. Это отдельный баланс от лимитов ChatGPT и Codex. [Кредиты API для подписчиков](https://help.openai.com/en/articles/20001626-api-credits-benefit-for-eligible-chatgpt-subscriptions)

### Пример одного запроса

Пример для установленного Python SDK `openai`. `source.png` — экспорт «Зеркалиуса» в рабочей папке, `OPENAI_IMAGE_MODEL` — необязательное имя модели из доступных проекту. Для чистого фона используем `client.images.generate` с текстовым заданием и без параметра `image`. [Документация Images API](https://developers.openai.com/api/docs/guides/image-generation) · [Параметры редактирования](https://developers.openai.com/api/reference/resources/images/methods/edit)

```python
from base64 import b64decode
from os import getenv
from pathlib import Path

from openai import OpenAI

client = OpenAI()
with Path("source.png").open("rb") as source:
    result = client.images.edit(
        model=getenv("OPENAI_IMAGE_MODEL", "gpt-image-2.5-sunburst"),
        image=source,
        prompt=(
            "Сохрани треугольник Зеркалиуса, его края и крупные пустоты. "
            "Сделай клетки похожими на бирюзовую керамику на тёмном графите. "
            "Без текста, логотипов и интерфейса."
        ),
        size="2048x1152",
        quality="medium",
        output_format="webp",
        n=1,
    )

Path("journal-illustration.webp").write_bytes(b64decode(result.data[0].b64_json))
```

Команда `tools/media-publish/media.ps1 generate-image` выполняет тот же шаг из
PowerShell и сохраняет ответ в локальный файл. [Настройка и примеры](../../tools/media-publish/README.md#генерация-через-openai-images-api)

## Как выпускаем запись

1. Исходники и готовые картинки сохраняем отдельными файлами в локальной папке `обои Зеркалиус` рядом с репозиторием сайта, вне Git. Точные кадры храним как PNG, иллюстрации и уменьшенные превью — как WebP, анимацию — как GIF, когда нужны её кадры и тайминг.
2. Публичные файлы загружаем в R2, бакет `zerkalius-media` с доменом `media.1001100.online`. Выпуску назначаем префикс `image-journal-ГГГГ-ММ-ДД/`. Используем понятные имена оригиналов и соответствующие `-preview.webp`. Для загрузки используем панель Cloudflare или подписанный S3-запрос `PutObject`. Чтение идёт по публичному домену, запись — с учётными данными R2 для этого бакета. Сверяем HTTPS-ответ, тип файла и, при необходимости, SHA-256 с локальным файлом. [Загрузка объектов R2](https://developers.cloudflare.com/r2/objects/upload-objects/) · [Публичный домен R2](https://developers.cloudflare.com/r2/buckets/public-buckets/) · [S3 API Cloudflare](https://developers.cloudflare.com/r2/api/s3/api/)
   Для загрузки из GitHub Actions используем `upload-r2` в workflow **Image Journal · R2 and VK**. В GitHub Releases можно приложить файл отдельно от истории Git. Подключение R2 и формат параметров описаны в [памятке медиа](../../tools/media-publish/README.md#загрузка-в-r2-через-github-actions).
3. В Git добавляем разметку, тексты, ссылки, настройки и воспроизводимые исходники. Бинарные оригиналы и превью остаются в R2. Ключи OpenAI, R2 и ВК держим вне Git, HTML, логов и публичных ссылок.
4. В `index.html` добавляем `article.entry` с постоянным `id` для ссылки на запись. На карточке `img` загружает превью с размерами и `alt`, а `a[data-view-image]` ведёт на оригинал. Просмотр закрывается кнопкой «В журнал», по Escape или кликом рядом с картинкой. «Файл в полном размере» открывает оригинал отдельно. Сохраняем шрифт с тенями Kraftwerk, цифры из тонкой АзъБукъ и видимую версию над заголовком. При обновлении поднимаем номер версии. Треугольный альбом остаётся отдельной работой.
5. Проверяем опубликованную страницу, ссылки на медиа и исходный режим. Для точного кадра сверяем номер кадра, геометрию, палитру и настройки просмотра. Приёмка интерфейса остаётся за владельцем проекта.

## Дублирование в ВК

Журнал остаётся местом, где лежат рецепт, оригинал и ссылка на исходное поле. В сообщество «Zerkalis» можно выпускать короткий анонс того же материала с одной картинкой и ссылкой на конкретную запись журнала. Подготовка может идти вместе. Сначала проверяем доступность записи на сайте, затем публикуем анонс в ВК и записываем ссылку на получившийся пост.

- «Работа с API → Ключи доступа → Создать ключ» выдаёт **ключ сообщества** для поддерживаемых методов управления. Перед настройкой проверяем, какой тип токена заявлен у нужного метода.
- Для записи **с фото** официальный контракт указывает **пользовательский токен** с доступом к нужным методам и правом публикации от имени сообщества. Сначала вызываем `photos.getWallUploadServer`, отправляем изображение на полученный адрес и сохраняем его через `photos.saveWallPhoto`. Затем вызываем `wall.post` с отрицательным `owner_id` группы, `from_group=1` и сохранённым вложением. Успешный `post_id` связываем с якорем записи журнала, чтобы при повторной попытке не создать дубль. [Схема методов фото VK](https://github.com/VKCOM/vk-api-schema/blob/master/photos/methods.json) · [Схема wall.post](https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json)
- Для автоматического анонса отметьте выбранную статью JSON-заявкой в папке `vk/` рядом с журналом. С полями `source_url` и `sha256` GitHub Actions сначала загрузит оригинал в R2 и проверит публичную ссылку. Затем он дождётся публикации записи и отправит анонс в «Zerkalis» с доступом `VK_USER_TOKEN`. [Настройка автоматического анонса](../../tools/media-publish/README.md#автоматический-анонс-выбранной-записи-в-vk)
