# Музыка телефона · ТЕЛ-001

Четыре новые композиции продолжают две собственные мелодии из «Синтеза». Две версии техно и две камерные пьесы созданы из тех же синтетических инструментов. Это аранжировки со специально выбранными мотивами, гармонией и формой; гармония не объявляется результатом физических законов.

| Композиция | Темп | Полная версия | Звонок | Поле |
|---|---:|---:|---:|---|
| Импульс восьми ветров | 126 | 78,190 с | 22,857 с | eight-winds: XOR, след восьми кадров |
| Медная орбита | 118 | 83,356 с | 24,407 с | copper-echo: накопление XOR |
| Письмо двух рек | 88 | 78,364 с | 21,818 с | two-rivers: встречные маятники, OR |
| Тонкий лёд | 76 | 77,789 с | 25,263 с | thin-ice: отражённые маятники, AND |

## Воспроизведение сборки

Из корня репозитория, Node.js и FFmpeg должны быть доступны в PATH:

```sh
node issledovanie/phone-theme/music/build-music.cjs
node issledovanie/phone-theme/music/check-music.cjs
```

Сборка пишет готовые файлы в `../audio/`, манифест в `../music.json`, партитуры JSON и MIDI рядом с этим файлом. Промежуточные несжатые WAV остаются во временной папке системы, её путь печатается в конце сборки. Они не нужны для работы сайта.

## Связь с маятниками

На каждую шестнадцатую приходится один действительный шаг исходного движка `mayatnik-synthesis-pendulums.js`, который вызывает `mayatnik-core.js`. Размер поля 385 × 128, глубина 128. Исходное поле шага 0 берётся до первого `step()`. Точная конфигурация каждого опыта хранится в соответствующем `*-score.json`.

Сопровождение получено через исходный `frameEvents()` из `mayatnik-synthesis-music.js`: плотность единиц, пересечения A/B и горизонтальные переходы влияют на динамику, некоторые события и высоты сопровождения. Исходная ведущая партия заменена новым мотивом. Плотность единиц поля управляет громкостью новой темы, а пространственные характеристики через исходный сонификатор — панорамой там, где он возвращает ведущую ноту. На остальных позициях новая тема звучит по центру. Выбранные лад, темп, гармонический цикл, ритм, разворот мотива в ответе, дублирование в репризе и финальный аккорд — композиционные решения автора генератора.

JSON-партитуры содержат все нотные события, мотив в ступенях, гармонический цикл, форму с временными отметками, состояние поля на каждом такте, полный хеш последовательности полей и контрольные суммы исходных файлов после нормализации CRLF → LF. MIDI сохраняет ноты и темп; тембры другого MIDI-проигрывателя могут отличаться от MP3.

В техно: вступление → тема → ответ → разрежение → реприза → кода. В камерных версиях: вступление → тема → ответ → реприза → кода. Для инструментов используется прежний синтез, затем мягкое короткое эхо и фильтрация низких частот. Громкость приводится к ориентиру RMS −17,5 dBFS для техно и −20 dBFS для камерных пьес с ограничением усиления по пику 0,70. Это ориентир RMS, не LUFS. Измеренный пик после сжатия записан отдельно.

## Звонки и уведомления

Четыре звонка вырезаны из готовых новых MP3, по целым музыкальным фразам. Есть MP3 и AAC в контейнере M4R. Входной фейд 25 мс, выходной 650 мс.

20 уведомлений — настоящие фрагменты **всех шести** мелодий: по четыре из двух исходных и по три из каждой новой. Никакие отдельные звуковые эффекты не подменяют вырезки. Манифест хранит точный `source`, `sourceId`, `sourceTitle`, `start`, `end`, контрольную сумму исходного MP3 и применённый FFmpeg-фильтр. Точки отсчёта относятся к декодированному аудио, без служебного MP3 encoder delay. Длительности 1,25–3,6 с. Входной фейд 18 мс, выходной 160 мс. MP3 — моно 44,1 кГц; небольшие WAV — моно PCM 16 бит 22,05 кГц.

Основные полные MP3 и рингтоны — стерео 44,1 кГц. MP3 кодируются libmp3lame quality 2; M4R — AAC 192 кбит/с. Уведомления переводятся в моно явно как (L + R) / 2, одинаково для WAV и MP3, без автоматического усиления при сведении каналов. Исходные две мелодии не изменены.

## Проверки и границы результата

`audio-checks.json` содержит результаты декодирования всех 52 аудиофайлов: длительность, кодек, число каналов, размер, SHA-256, RMS, обычный пик и пик после пересчёта на 176,4 кГц, количество отсечённых отсчётов, тишину и граничные отсчёты. Пересчёт частоты — практическая проверка межотсчётных пиков, не сертифицированный измеритель true peak.

Каждый WAV уведомления независимо повторно извлекается из указанного MP3 с указанными фейдами. Проверяется полное совпадение декодированного PCM, а не только наличие похожего сигнала. Положительный итог этих измерений не заменяет субъективную музыкальную оценку и установку мелодий на физический телефон: эти две проверки здесь не выполнялись.
