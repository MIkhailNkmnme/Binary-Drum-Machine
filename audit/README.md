# Проверка страниц Зеркалиуса

Запускаем вручную раз в неделю и после публикации новой страницы или изменений, которые затрагивают несколько страниц. При таком выпуске первым делом проверяем затронутые сценарии, затем сохраняем полный прогон. [История и реестр по датам](reports/).

## Запуск

Из корня Binary-Drum-Machine. Нужны Git, Node.js 22 или новее и установленный Chrome.

```powershell
git pull --ff-only
npm.cmd --prefix audit ci
npm.cmd --prefix audit run check
```

`npm ci` нужен при первом запуске или изменении файла зависимостей. Если обновление Git завершилось ошибкой, сверяем ревизию прежде чем проверять опубликованную версию. Для Edge добавляем `-- --channel msedge` к команде запуска. В терминале Linux или macOS используем `npm` вместо `npm.cmd`.

По умолчанию проверяется адрес из `CNAME`. Для своего запущенного HTTP-сервера используем `npm.cmd --prefix audit run check -- --base http://127.0.0.1:8766/`. В отдельном терминале сервер можно запустить из корня командой `python -m http.server 8766 --bind 127.0.0.1`.

Если локальный клон отстаёт и обновление Git не проходит, список для проверки публичного сайта можно взять прямо из ветки `main` на GitHub.

```powershell
$auditTreeFile = Join-Path ([System.IO.Path]::GetTempPath()) 'zerkalius-site-tree.json'
Invoke-WebRequest 'https://api.github.com/repos/MIkhailNkmnme/Binary-Drum-Machine/git/trees/main?recursive=1' -OutFile $auditTreeFile
npm.cmd --prefix audit run check -- --tree $auditTreeFile
```

## Реестр и пополнение

Каждый файл в `audit/reports/` — снимок реестра по всем HTML из Git на момент запуска. Включены служебные, экспериментальные, архивные страницы и старые адреса с перенаправлением, если их HTML входит в дерево сайта. Текущий снимок — последний отчёт с суффиксом `-site.md`. Локальные прогоны имеют отдельную историю. При повторном запуске новые страницы автоматически получают отметку, исчезнувшие перечисляются отдельно. HTML без Git выводится в шапке как ожидающий проверки.

1. Для новой страницы проверить открытие по публичному URL и переход на неё из соответствующего раздела. Пройти её основной сценарий и записать его в отчёт. Для изменённой страницы проверить затронутый сценарий. После изменений в общих скриптах или стилях открыть их основные страницы-потребители.
2. В колонке **Ручной сценарий** заменить «Ожидает» на «Пройден», «Ошибка» или «Не применимо» с кратким пояснением. Для ошибки записать устройство, действия, ожидание и результат. Статус ручной проверки относится к конкретным дате и ревизии. Для переноса открытой находки в следующую проверку использовать ссылку на задачу.
3. В `ЗАДАЧИ.md` открыть карточку подтверждённого дефекта или оптимизации с URL, измерением, шагами и критерием приёмки. После исправления пройти исходный сценарий повторно, добавить результат в новый отчёт и закрыть карточку. Хранить отчёты в Git, чтобы история была общей для разных машин.

Код завершения `1` при сигналах об ошибках или неучтённом HTML ожидаем. Путь к созданному отчёту выводится в конце. Если отчёт отсутствует, прогон не завершился.

## Ручные сценарии

| Страницы | Основной сценарий |
|---|---|
| Все | Открыть с ПК и телефона. Проверить доступность основного действия, навигацию, читаемость и отсутствие незадуманного перекрытия. |
| Хаб, Синхрофазотрон, Синхроромб, Зазеркалиус | Задать параметры, сделать шаг, запустить и остановить. Включить поддерживаемые режимы и проверить возврат, масштаб, звук по нажатию и сохранение после F5 там, где они предусмотрены. |
| Маятник, варианты, Синтез и Kraftwerk/Glyphen | Построить небольшой пример, сделать шаг, запустить и остановить. Проверить открытие сохранённой работы или ссылки, выбранные режимы 2D/3D, XOR и перенос между связанными страницами там, где это доступно. |
| Битотека, окно кадра, библиотека, просмотр, результаты | Открыть по ссылке с тестовыми данными, проверить пустое состояние, загрузку и возврат. Сохранять и удалять только временные записи в отдельном профиле. |
| Исследования, инструкции, статьи, витрины | Перейти к вложенному материалу и обратно, проверить якоря, показ демонстраций и запуск видео по нажатию. |
| Перенаправления и замороженные страницы | Проверить адрес назначения и параметры ссылки, если они служат частью контракта. Для замороженной страницы проверить открытие и доступ к документированным функциям. |

## Оценка производительности

Прогон открывает каждую страницу в чистом контексте на 1440 и 390 px. Фиксирует ошибки JavaScript, сетевые сбои и HTTP 4xx/5xx при загрузке, соответствие HTML снимку, внутренние ссылки на отсутствующие в Git пути, ширину документа, тайминги запуска, переданные байты и долгие задачи главного потока. Внутренние ссылки сверяются по путям без проверки якорей и query. Проверка внешних ссылок, реальный мобильный GPU, звук, работа Canvas после действий и визуальная приёмка входят в ручную часть.

Для сравнения скорости повторить замер в одном потоке (`-- --workers 1`) и на той же машине. Для подозрительной страницы сделать три холодных замера и взять медиану. В Chrome DevTools записать Performance для основного сценария и пройтись по Network по убыванию Size. Блокировки после «Пуск» и во время перестроения оценивать отдельно от начальной загрузки. В карточку оптимизации записать показатели до и после с одинаковым примером и профилем. Приоритет у невозможности открыть страницу или выполнить действие, затем у повторяемых задержек, передачи лишних ресурсов и мобильной компоновки.
